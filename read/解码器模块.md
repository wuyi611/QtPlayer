# PonyPlayer 解码器模块（decoder/）依赖与调用关系

> 本文档梳理 `src/decoder/` 目录下各文件的职责、静态依赖（include）关系与运行时调用链。
> 生成于 2026-08-15。

---

## 一、模块定位与目录结构

解码层把媒体文件**解封装（demux）→ 解码（decode）→ 产出音视频帧**，供上层 FRAME 线程渲染、音频线程播放消费。整体以 `Demuxer` 为对外门面，以"正放 / 倒放"两条调度器管线为骨架，是典型的分层结构。

```
src/decoder/
├── CMakeLists.txt         构建配置
├── demuxer.hpp            对外门面（协调者）
├── frame.hpp              帧数据结构（音视频帧封装）
├── helper.hpp             常量 + FFmpeg 错误处理
└── private/               内部实现（对外不可见）
    ├── dispatcher.hpp     调度器：基类 + 正放 + 倒放
    ├── decoders.hpp       解码器抽象接口 + FFmpeg 上下文
    ├── forward.hpp        正向解码器实现
    ├── backward.hpp       反向解码器实现
    ├── virtual.hpp        虚拟视频解码器
    └── previewer.hpp      缩略图预览器（旁支）
```

## 二、各文件职责

| 文件 | 作用 |
|---|---|
| `demuxer.hpp` | **核心协调者 / 对外唯一门面**。内部持有 `DecodeDispatcher`（正放）和 `ReverseDecodeDispatcher`（倒放）两条管线，用 `m_worker` 指针切换活跃者。负责 open/seek/backward/forward/close 等生命周期控制，以及向 FRAME/音频线程提供 `getPicture/getSample/frontPicture/frontSample` 等线程安全的帧获取接口。所有公开方法在独立 DECODER 线程执行，用 `m_workerLock` 互斥保护。 |
| `frame.hpp` | **帧数据结构**。定义 `VideoFrame`（AVFrame + 引用计数，RAII）、`VideoFrameRef`（引用计数智能句柄）、`AudioFrame`（裸采样数据）。队列与渲染管线之间传递的就是这些对象。 |
| `helper.hpp` | **基础设施**。FFmpeg 错误码常量（`ERROR_EOF`、`MAX_AUDIO_FRAME_SIZE` 等）和 `ffmpegErrToString()` 错误转字符串工具，几乎被全部文件依赖。 |
| `private/dispatcher.hpp` | **调度器核心（最重）**。含四部分：`StreamInfo`（流信息）、抽象基类 `DemuxDispatcherBase`（持有 `fmtCtx` 解封装上下文，定义统一接口）、`DecodeDispatcher`（正向调度器，`onWork` 循环读包→分发→入队）、`ReverseDecodeDispatcher`（反向调度器，"分段向前解码、内存倒序输出"实现倒放）。 |
| `private/decoders.hpp` | **抽象层**。定义解码器接口 `IDemuxDecoder`（统一"收 Packet → 出 Frame"行为，含正放接口 + 倒放专用的分段推进接口 `setFollower/pushFrameStack/nextSegment` 等）和 `DecoderContext`（封装 FFmpeg 解码器初始化/释放的 RAII 基础设施）。定义 `Audio/Video/Common` 模板类型别名。正反向解码器都继承它。 |
| `private/forward.hpp` | **正向解码器**。模板 `DecoderImpl<type>` 实现通用"送包-取帧"解码协议；`DecoderImpl<Audio>` 特化增加重采样（SwrContext）；`DecoderImpl<Video>` 特化处理"第一帧是封面"的情况。 |
| `private/backward.hpp` | **反向解码器**。模板 `ReverseDecoderImpl<type>`，实现分段解码：把一段内的帧存入 `frameStack`，follower 追上 leader 时整段**倒序**压入队列。音频特化还做倒序重采样（`reverseSample`）。 |
| `private/virtual.hpp` | **虚拟视频解码器**。纯音频文件（mp3/wav）无视频轨，用它模拟一条时长等于音频长度的"空视频轨"，让上层视频渲染管线不阻塞。 |
| `private/previewer.hpp` | **缩略图预览器（旁支）**。独立继承 `DemuxDispatcherBase`，不走正常解码管线，只负责 seek 到指定位置解出**单张**视频帧，用于进度条缩略图预览。 |

### 各文件实际 include 一览（已核实）

| 文件 | include |
|---|---|
| `helper.hpp` | libavutil/error.h, QString |
| `frame.hpp` | helper.hpp, ponyplayer.h, libavformat/avformat.h |
| `decoders.hpp` | helper.hpp, frame.hpp, twins_queue.hpp, concurrentqueue.h, audioformat.hpp, FFmpeg 系列 |
| `forward.hpp` | decoders.hpp |
| `backward.hpp` | **（无任何 include）** |
| `virtual.hpp` | **（无任何 include）** |
| `dispatcher.hpp` | forward.hpp, backward.hpp, virtual.hpp, frame.hpp, helper.hpp, twins_queue.hpp, audioformat.hpp, FFmpeg 系列 |
| `demuxer.hpp` | dispatcher.hpp, audioformat.hpp |
| `previewer.hpp` | dispatcher.hpp, QImage, libswscale/swscale.h |

### 关键事实

- `helper.hpp` 是最底层，被几乎所有文件依赖。
- `dispatcher.hpp` 是**汇合点**：一次性把所有解码器拼装成正/反向调度器。
- `forward.hpp` 是唯一"自给自足"的实现类头文件；`backward.hpp` / `virtual.hpp` **零 include**，完全依赖 dispatcher.hpp 的 include 顺序间接带进声明（见下文"传递包含"隐患）。

## 四、类继承关系

```
QObject
 └─ DemuxDispatcherBase（抽象基类：持有 fmtCtx 解封装上下文）
     ├─ DecodeDispatcher        正放调度器
     ├─ ReverseDecodeDispatcher 倒放调度器
     └─ Previewer               缩略图预览（旁支）

IDemuxDecoder（解码器抽象接口）
 ├─ DecoderImpl<Audio/Video/Common>         正向解码器（forward.hpp）
 ├─ ReverseDecoderImpl<Audio/Video/Common>  反向解码器（backward.hpp）
 └─ VirtualVideoDecoder                    虚拟视频解码器（virtual.hpp）

DecoderContext（FFmpeg 解码器初始化/释放，被 forward/backward/previewer 复用）
 ├─ DecoderImpl<Common>（多继承 IDemuxDecoder）
 └─ ReverseDecoderImpl<Common>
```

## 五、运行时调用链

### 5.1 构造阶段（`Demuxer::openFile` → dispatcher 构建管线）

```
Demuxer::openFile(fn)
 ├─ new DecodeDispatcher(fn, result, ...)      ← 正放
 │    ├─ new TwinsBlockQueue<AVFrame*> audioQueue(容量16)
 │    ├─ videoQueue = audioQueue->twins(...)   ← 孪生队列，共享锁/条件变量（音视频同步关键）
 │    ├─ new DecoderImpl<Audio>(流, audioQueue)
 │    ├─ new DecoderImpl<Video> 或 VirtualVideoDecoder（纯音频时）
 │    └─ connect(signalStartWorker → onWork, QueuedConnection)  ← 解码循环投递到 DECODER 线程
 ├─ new ReverseDecodeDispatcher(fn, this)      ← 倒放，结构类似
 │    ├─ new ReverseDecoderImpl<Audio>(流, audioQueue 容量200)
 │    ├─ new ReverseDecoderImpl<Video> 或 VirtualVideoDecoder
 │    └─ 绑定 primary/follower 关系：
 │         视频文件：primary=videoDecoder, videoDecoder.setFollower(audioDecoder)
 │         纯音频：  primary=audioDecoder（自己跟随自己）
 └─ m_worker = m_forward（默认正放）
```

`DecoderImpl`/`ReverseDecoderImpl` 构造时通过 `DecoderContext` 完成：查解码器 → 分配 context → 拷贝参数 → open → 分配帧缓冲。

### 5.2 解码主循环（DECODER 线程，经信号槽触发）

**正放 `DecodeDispatcher::onWork`：**

```
av_read_frame(fmtCtx, packet)  ← 读压缩包
 ├─ 视频包 → videoDecoder->accept(packet, interrupt)   → avcodec_send_packet
 │                                                    → 循环 avcodec_receive_frame
 │                                                    → AVFrame 压入 videoQueue
 ├─ 音频包 → m_audioDecoder->accept(...)              → 压入 audioQueue
 └─ EOF   → 两个队列都 push(nullptr) 哨兵，break
```

**倒放 `ReverseDecodeDispatcher::onWork`：**

```
读包 → 分发到 videoDecoder / m_audioDecoder 的 accept
accept 把落在 [from-interval, from) 段的帧存入各自 frameStack
当 leader 的 follower 追上（getLastPts() >= from）→ pushFrameStack() 整段【倒序】压入队列
每轮检查 primary->nextSegment()：
  next > 0 → 起点前移一个 interval，重新 av_seek_frame 到更早位置，解下一段
  next == 0 → 已到文件起点，push(nullptr)，结束
```

### 5.3 消费阶段（FRAME/音频线程 ←→ Demuxer 门面）

```
Demuxer::getPicture()  → m_worker->getPicture()  → DecoderImpl<Video>::getPicture() → videoQueue->remove(true)
Demuxer::getSample()   → m_worker->getSample()   → DecoderImpl<Audio>::getSample()
                                                   → 出队AVFrame + swr_convert 重采样 → AudioFrame
Demuxer::frontPicture()/frontSample() → viewFront()  队列只读不弹
Demuxer::skipPicture()/skipSample()   → skip(predicate)  线性跳过
```

### 5.4 控制调用（FRAME 线程触发，操作前须先 `pause()`）

| 门面方法 | 底层调用 | 作用 |
|---|---|---|
| `pause()` | `statePause()` | interrupt=true + 队列 close，唤醒阻塞者 |
| `seek(s)` | `dispatcher::seek()` | av_seek_frame + flushFFmpegBuffers |
| `flush()` | `dispatcher::flush()` | 清空队列旧帧；倒放额外清 frameStack |
| `start()` | `stateResume()` | 重新 open 队列 + emit signalStartWorker 重启 onWork |
| `backward()`/`forward()` | 切换 m_worker 指向 | 并 flush 另一条管线 |

### 5.5 Previewer（旁支，不经过 Demuxer）

`Previewer::previewRequest(pos)`：直接用它自己的 `DecoderContext`，`av_seek_frame` → `avcodec_send_packet/receive_frame` 解出**单张**帧返回，用完即弃。

## 六、跨文件数据流

```
[demuxer.hpp] 门面
    │
[dispatcher.hpp] 调度器.onWork          AVPacket（压缩数据）
    │  av_read_frame ──────────────► [decoders.hpp] 解码器 accept
    │                                     │ 解码成 AVFrame
    │                                     ▼
    │                       TwinsBlockQueue<AVFrame*>（frame.hpp 帧经此流转）
    │                                     │
    └──── getPicture/getSample ◄─────────┘ 消费线程阻塞取出
```

## 七、传递包含隐患（backward.hpp / virtual.hpp）

**传递包含**：A 头文件用到了 B 的符号，但 A 自己不 include B，而是靠"别人先 include 了 B"间接带进来。

`backward.hpp` 与 `virtual.hpp` **零 include**，能编译通过纯粹因为 `dispatcher.hpp` 的 include 顺序（forward.hpp → decoders.hpp 在前）。隐患：

1. **顺序敏感**：若 dispatcher.hpp 把 backward.hpp 挪到 forward.hpp 前，立刻编译失败。
2. **不能独立使用**：单独 include 它们的翻译单元会报未声明标识符。
3. **隐式耦合**：依赖关系藏在 include 顺序里，改动易被破坏。

**修复建议**：给 `backward.hpp` 和 `virtual.hpp` 补上最小依赖 include（`decoders.hpp`、`frame.hpp`、`twins_queue.hpp`、`audioformat.hpp`），使它们自给自足。

## 八、线程模型

```
DECODER 线程  ← Demuxer 对象、正/反向 Dispatcher、解码器（onWork 解码循环）
FRAME 线程    ← getPicture/getSample 等帧获取（经 m_workerLock + 联动队列阻塞读取）
音频线程      ← getSample 音频消费
```

- `TwinsBlockQueue`（utils/twins_queue.hpp）是音视频联动队列，共享同一把锁/条件变量，保证音视频帧同步。
- 控制接口（statePause/seek/flush/stateResume）标注 `PONY_GUARD_BY(FRAME)`；帧获取接口标注 `PONY_THREAD_SAFE`。
