# PonyPlayer 播放器模块（player/）依赖与调用关系

> 本文档梳理 `src/player/` 目录下各文件的职责、静态依赖（include）关系与运行时调用链。
> 生成于 2026-08-16。

---

## 一、模块定位与目录结构

播放器模块是 PonyPlayer 的**播放核心**：向上以 QML 组件（`HurricanePlayer`、`Thumbnail`）暴露给界面层，向下消费 `decoder` 模块产出的音视频帧并驱动 `audiosink` 模块输出。整体是"QML 组件（GUI）→ 帧控制器（FRAME）→ 输出层（PLAYBACK）→ 渲染层（RENDER）"的多线程分层结构。

```
src/player/
├── CMakeLists.txt         构建配置（静态 QML 模块，URI=player）
├── include/players.h      对外接口：registerPlayerQML() 声明
├── players.cpp            QML 类型注册入口（HurricanePlayer / Thumbnail）
├── hurricane.hpp          QML 组件 HurricanePlayer：状态机 + 全部控制 API
├── framecontroller.hpp    帧控制器 FrameController（FRAME 线程协调者）
├── playback.hpp           音视频输出 Playback（PLAYBACK 线程）
├── fireworks.hpp          视频渲染 QQuickItem（GUI 线程 → 场景图）
├── renderer.hpp           FireworksRenderer（自定义 QSGRenderNode + OpenGL 渲染）
├── updatevalue.hpp        双缓冲设置模板 UpdateValue<T>（线程间设置同步）
├── preview.hpp            缩略图预览封装 Preview（PreviewThread）
├── thumbnail.hpp          缩略图 QML 组件 Thumbnail（旁支）
└── shader/                顶点 / 片段着色器资源（:/player/shader/...）
```

依赖关系（构建层面）：`player` 链接 `decoder`（Demuxer / 帧 / Previewer）与 `audiosink`（PonyAudioSink），以及 Qt Core/Gui/Qml/Widgets/Quick。

## 二、各文件职责

| 文件 | 作用 |
|---|---|
| `players.cpp` | **模块入口**。`registerPlayerQML()` 把 `Hurricane` 注册为 QML 类型 `HurricanePlayer`（1.0）、`Thumbnail` 注册为 `Thumbnail`，由 `src/main.cpp` 启动时调用。 |
| `hurricane.hpp` | **对外 QML 组件（门面）**。继承 `Fireworks`。定义 7 态播放状态机（`INVALID/LOADING/CLOSING/PRE_PLAY/PLAYING/PRE_PAUSE/PAUSED`，其中 `PRE_*` 为瞬时状态）与全部 `Q_INVOKABLE` 控制 API（openFile/start/pause/close/seek/setSpeed/setVolume/setPitch/setTrack/forward/backward 等）。所有请求转成带 `QPrivateSignal` 的信号投递给 FrameController，通过 `stateChanged/openFileResult` 等信号回传状态。 |
| `framecontroller.hpp` | **中间协调层**。运行在 FRAME 线程，持有 `Demuxer`（DECODER 线程）与 `Playback`（PLAYBACK 线程），编排两者的生命周期：文件打开后的格式协商、seek（阻塞连接）、音轨/方向切换、设备切换与倍速越界时的整体重同步。 |
| `playback.hpp` | **输出层**。运行在 PLAYBACK 线程，负责把解码帧输出到渲染器（视频）与 `PonyAudioSink`（音频），`onWork` 主循环取帧→发帧→写音频→`syncTo` 按音频时钟睡眠实现音视频同步（支持纯音频固定 1/30s 节奏、倍速>2x 跳帧、暂停条件变量唤醒）。 |
| `fireworks.hpp` | **渲染桥**。`QQuickItem` 子类，`setVideoFrame()` 接收帧 → `update()` 触发重绘；重写 `updatePaintNode()` 返回 `FireworksRenderer`；暴露亮度/对比度/饱和度/帧尺寸/LUT/Shader 滤镜等 QML 属性。 |
| `renderer.hpp` | **OpenGL 渲染器**。`FireworksRenderer` 多继承 `QSGRenderNode` + `QOpenGLFunctions_3_3_Core`，在 RENDER 线程 `init`（建着色器/YUV 纹理/VAO）与 `render`（上传 Y/U/V 纹理 + LUT 滤镜 + 亮度对比度饱和度，`glDrawElements` 出图）。 |
| `updatevalue.hpp` | **双缓冲模板**。`UpdateValue<T>` 带脏标志（`m_update`），`UpdateValueVideoFrameRef` 增加尺寸变化标志（`m_updateSize`）。GUI 线程写 `mainSettings`，渲染线程 `sync()` 阶段经 `updateBy()` 一次性合并到 `renderSettings`，解决跨线程内存可见性。 |
| `preview.hpp` | **预览封装**。运行在 PreviewThread，把 `previewRequest(pos)` 转发给 decoder 模块的 `Previewer`（`private/previewer.hpp`），通过信号异步回传单帧画面。 |
| `thumbnail.hpp` | **缩略图 QML 组件（旁支）**。继承 `Fireworks`，`windowChanged` 时经 QML context 反查 `m_player` 指定的 `Hurricane` 实例并挂钩其 openFile/close，实现进度条悬停预览。 |

### 关键事实

- `updatevalue.hpp` 是最底层，被渲染链依赖；`frame.hpp`（decoder 模块）是所有帧对象的源头。
- `playback.hpp` 是播放链的汇合点：同时依赖 decoder（demuxer/frame）与 audiosink 两个模块。
- `preview.hpp` 直接 include decoder 模块的**私有实现** `private/previewer.hpp`（能解析成功依赖 decoder 的 CMakeLists 把自身目录导出为 PUBLIC include）——跨模块私有耦合（见第八节隐患 1）。

## 五、运行时调用链

### 5.1 构造阶段（main → QML 注册 → 组件创建 → 线程初始化）

```
main.cpp: registerPlayerQML()
 ├─ qmlRegisterType<Hurricane>("HurricanePlayer", 1, 0, "HurricanePlayer")
 └─ qmlRegisterType<Thumbnail>("Thumbnail", 1, 0, "Thumbnail")

QML 创建 HurricanePlayer → Hurricane 构造（GUI 线程）
 ├─ new FrameController(this)
 ├─ 控制信号 → FrameController：signalStart/signalPause/signalOpenFile/signalClose/signalSeek
 ├─ 回传信号 → Hurricane 槽：openFileResult / setPicture / playbackStateChanged /
 │             signalPositionChangedBySeek / signalAudioOutputDevicesChanged / resourcesEnd
 └─ emit signalPlayerInitializing

FrameController 构造
 ├─ new QThread（名 "FrameControllerThread"）+ moveToThread
 ├─ connect(QThread::started → initOnThread)
 └─ start()

initOnThread（FRAME 线程）
 ├─ new Demuxer{this}                        ← DECODER 线程（decoder 模块）
 ├─ new Playback{m_demuxer, this}            ← PLAYBACK 线程
 ├─ setPicture / stateChanged / resourcesEnd → DirectConnection 转发
 ├─ signalDecoderOpenFile → Demuxer::openFile
 ├─ signalDecoderSeek    → Demuxer::seek（Qt::BlockingQueuedConnection，必须等完成）
 └─ Demuxer::openFileResult → lambda：setDesiredFormat/setOutputFormat → demuxer->start()
                                 → playback->clearCacheFrame() → playback->showFrame() → emit openFileResult

Playback 构造
 ├─ new QThread（名 "PlaybackThread"）+ moveToThread
 ├─ startWork → onWork；stopWork → audioSink->stop；setAudioStartPoint/Volume/Pitch/Speed → audioSink
 ├─ showFirstVideoFrame → ① 预取首帧并 emit setPicture ② 清空缓存（两个 lambda 顺序执行）
 └─ connect(QThread::started → 创建 PonyAudioSink + 设备信号转发 + 首次设备列表广播)
```

### 5.2 播放流程（openFile → start → 帧主循环）

```
QML openFile(url)
 └─ Hurricane::openFile（状态机：INVALID/CLOSING → LOADING，重置倒放标志）
     └─ emit signalOpenFile ──► FrameController::openFile（FRAME）
         └─ emit signalDecoderOpenFile ──► Demuxer::openFile（DECODER）
             └─ openFileResult ──► lambda（设格式→启动解码→清缓存→显示首帧）
                 └─ emit openFileResult ──► Hurricane::slotOpenFileResult（→ PAUSED）

QML start()
 └─ Hurricane::start（PAUSED → PRE_PLAY）
     └─ signalStart ──► FrameController::start
         ├─ Demuxer::start（DECODER 恢复解码循环）
         └─ Playback::start → signalStartWork → onWork（PLAYBACK 线程）

onWork 主循环（PLAYBACK 线程）:
     getVideoFrame → emit setPicture(pic) → writeAudio(10×speed) → processEvents → syncTo(pic.PTS)
     ├─ setPicture ──(Direct)──► FrameController::setPicture ──(队列)──► Hurricane::setVideoFrame（GUI）
     │    └─ Fireworks::setVideoFrame → update() → sync/init/render（RENDER 线程）
     ├─ syncTo：按音频时钟（或纯音频 1/30s）睡眠；倍速>2x 先 skipPicture 跳帧；
     │          暂停时由 m_interruptCond 立即唤醒
     └─ 视频/音频取尽 → m_audioSink->waitComplete() → emit resourcesEnd
```

### 5.3 控制操作（pause / seek / 方向切换 / 音轨切换）

```
pause:  Hurricane::pause（PLAYING→PRE_PAUSE）→ signalPause → FrameController::pause → Playback::pause
        ├─ m_isInterrupt=true + m_interruptCond.notify_all()（唤醒 syncTo 睡眠）
        └─ 阻塞等待 m_workMutex（onWork 退出放锁）→ stateChanged → slotPlaybackStateChanged → PAUSED

seek:   Hurricane::seek（状态校验 + 区间校验 [0, duration] → PRE_PAUSE）→ signalSeek
        └─ FrameController::seek（FRAME 线程完整流程）:
            Playback::stop → Demuxer::pause（阻塞）→ signalDecoderSeek（阻塞等待）→ flush → start
            → 正放：skipPicture/skipSample 跳过目标位置之前的帧，记录起始帧 PTS
            → 倒放：取 frontPicture 作为起始点（dispatcher 已保证帧就绪）
            → signalPositionChangedBySeek → setStartPoint → showFrame

forward/backward（方向切换）: Hurricane → FrameController::forward()/backward()（PONY_THREAD_SAFE）
        └─ signalForward/signalBackward → lambda（FRAME）:
            保存 pos → Playback::stop → Demuxer::pause → Demuxer::forward/backward → seek(pos) → Demuxer::start

setTrack（音轨切换）: 保存 pos → stop → pause → signalDecoderSetTrack → 重设音频格式 → seek(pos)
```

### 5.4 设备切换 / 倍速越界（重同步链路）

```
QML setCurrentOutputDevice → Hurricane → FrameController::setSelectedAudioOutputDevice
  → Playback::setSelectedAudioOutputDevice → signalSetSelectedAudioOutputDevice
  → PonyAudioSink::requestDeviceSwitch → signalDeviceSwitched
      ├─ Playback 转发 → FrameController::signalDeviceSwitched → Hurricane::currentOutputDeviceChanged
      └─ 同时 emit requestResynchronization(enableAudio, updateAudioFormat)
          └─ FrameController lambda（QueuedConnection）: 保存 pos → stop → pause
             →（updateAudioFormat 时重设格式）→ setEnableAudio → seek(pos) → start（若原在播放）

倍速 setSpeed：speed > MAX_SPEED_FACTOR → 禁用音频（setBlockState(true)）+ requestResynchronization(false, false)
             speed 回落 → 重新启用音频 + requestResynchronization(true, false)
```

### 5.5 渲染（RENDER 线程）

```
Fireworks::setVideoFrame（GUI 线程）
 ├─ m_renderer->setVideoFrame(frame) → mainSettings.videoFrame 置脏（UpdateValue）
 ├─ this->update()（帧尺寸变化时同时更新宽/高/宽高比并 emit frameSizeChanged）
 └─ Qt Quick 场景图：
    beforeSynchronizing → FireworksRenderer::sync → renderSettings.updateBy(mainSettings)（双缓冲合并）
    beforeRendering      → FireworksRenderer::init（首次：链接着色器、建 Y/U/V/LUT 纹理、VAO/VBO）
    QSGRenderNode::render → 设 uniform（亮度/对比度/饱和度）
        → 按 isUpdateSize() 全量 glTexImage2D / isUpdate() 增量 glTexSubImage2D 上传 Y/U/V + LUT
        → 视口适配（保持宽高比，居中留黑边）→ glDrawElements 出图
```

### 5.6 缩略图预览（旁支，不经过播放管线）

```
QML Thumbnail 组件 → windowChanged 时经 qmlContext 逐层向上查找 id 为 m_player 的 Hurricane 实例
 ├─ connect(Hurricane::signalOpenFile → Preview::openFile)（PreviewThread 执行，复用同一文件）
 ├─ connect(Hurricane::signalClose   → Preview::close)
 └─ Thumbnail::previewRequest(pos) → Preview::previewRequest → Previewer::previewRequest
     ├─ av_seek_frame(pos) → 解码单张帧 → VideoFrameRef（decoder/private/previewer.hpp）
     └─ previewResponse → Thumbnail::slotPreviewResponse → setVideoFrame 显示
```

## 七、线程模型

```
MAIN/GUI 线程    ← Hurricane、Fireworks、mainSettings、updatePaintNode
FRAME 线程       ← FrameController 全部槽（initOnThread/openFile/seek/start/stop/close...）
DECODER 线程     ← Demuxer（decoder 模块，解码循环）
PLAYBACK 线程    ← Playback + PonyAudioSink（onWork 播放循环）
RENDER 线程      ← FireworksRenderer::sync / init / render
PreviewThread    ← Preview::previewRequest / openFile / close（缩略图旁支）
```

- 线程名常量定义于 `utils/include/ponyplayer.h`：`PLAYBACK/DECODER/MAIN/RENDER/PREVIEW/FRAME`。
- 线程标注：`fireworks.hpp` / `renderer.hpp` 用 `PONY_GUARD_BY(MAIN)` + `PONY_GUARD_BY(RENDER)` 区分双缓冲；`playback.hpp` 内部用 `PONY_GUARD_BY(PLAYBACK)`；FrameController 跨线程 getter 标 `PONY_THREAD_SAFE`。
- 跨线程通信原则：**控制走 Qt 队列连接**（信号带 `QPrivateSignal`，只能由所属类内部 emit）；**帧走直连 + 队列混合**——Playback→FrameController 用 `DirectConnection`（同线程链），FrameController→Hurricane 靠跨线程自动队列连接落到 GUI 线程；seek 用 `BlockingQueuedConnection` 保证同步完成。

## 八、注意点与隐患

1. **跨模块私有依赖**：`preview.hpp` 的 `#include "private/previewer.hpp"` 实际解析到 `decoder/private/previewer.hpp`——player 模块直接使用了 decoder 模块的"私有"实现头。能编译成功只是因为 decoder 的 CMakeLists 把自身目录导出为 `PUBLIC` include。若 decoder 调整 include 导出或移动/重命名该文件，player 立即编译失败。建议把 Previewer 归入 decoder 对外接口或改为由 player 侧封装。
2. **include guard 命名遗留**：`playback.hpp` 的 guard 是 `PONYPLAYER_VIDEOWORKER_H`（旧类名 VideoWorker），与类名 `Playback` 不符；`framecontroller.hpp` 类文档中同样残留 "VideoWorker" 字样。
3. **hurricane.hpp 双重 QML_ELEMENT**：第 31 行（带 `QML_ADDED_IN_VERSION(1, 0)`）与第 49 行重复声明 `QML_ELEMENT`，冗余但无害。
4. **Fireworks 构造日志沿用旧名**：打印 `"Create Hurricane QuickItem."`，与实际类名不符。
5. **updatevalue.hpp 疑似写反 + 脏标志不复位**：
   - `UpdateValueVideoFrameRef::operator=` 中 `if (m_value.isSameSize(videoFrame)) { m_updateSize = true; }` 疑似写反——`m_updateSize` 语义是"纹理需要重新分配"，应在**尺寸变化**（`!isSameSize`）时置位。
   - 渲染线程侧 `renderSettings.videoFrame` 的脏标志只经 `updateBy()` 置位、从不复位（`render()` 不调用 `getUpdate()`），导致 `isUpdate()`/`isUpdateSize()` 恒为 true，增量上传分支（`glTexSubImage2D`）实际是死代码，每帧都走全量 `glTexImage2D`。
6. **Playback::showFirstVideoFrame 双连接**：同一信号挂两个 lambda（① 预取并发送首帧 ② 清空缓存），依赖 Qt 按连接顺序执行槽的语义，顺序耦合较隐晦。
7. **空指针/竞争保护不一致**：`FrameController::getPreferablePos()` 直接解引用 `m_playback`（无空指针保护），而 `getPitch()/getAudioDeviceList()` 有保护。实际由 FRAME 线程队列时序保证 `initOnThread` 先于所有控制调用执行，但 GUI 线程跨线程读 `m_playback` 指针本身无同步，属潜在数据竞争。
