## 1. 总体架构概览

PonyPlayer 采用分层架构，状态机分布在不同的层次中：

```
┌──────────────────────────────────────────────────┐
│  QML UI Layer (main.qml)                         │
│  UI flags: isPlay, isFullScreen, isInverted ...  │
│  Widget visibility: isFooterVisible, isVideo...  │
├──────────────────────────────────────────────────┤
│  Hurricane (QML ↔ C++ bridge)                    │
│  ┌─ HurricaneState ──────────────────────────┐   │
│  │ CLOSING → LOADING → INVALID               │   │
│  │ PAUSED ⇄ PRE_PLAY/PRE_PAUSE ⇄ PLAYING     │   │
│  └────────────────────────────────────────────┘   │
├──────────────────────────────────────────────────┤
│  FrameController (thread: FRAME)                  │
│  Coordinates Demuxer ↔ Playback                   │
├──────────────────────┬───────────────────────────┤
│  Playback            │  Demuxer                   │
│  (thread: PLAYBACK)  │  (thread: DECODER)         │
│  ┌─ m_isPlaying ─┐   │  ┌─ m_worker ──────────┐   │
│  │ true / false   │   │  │ forward / backward  │   │
│  └────────────────┘   │  │ / nullptr           │   │
│  ┌─ m_isInterrupt─┐   │  └────────────────────┘   │
│  │ true / false   │   │                           │
│  └────────────────┘   │  DecodeDispatcher         │
│  PonyAudioSink        │  ┌─ interrupt ─────────┐  │
│  ┌─ PlaybackState─┐   │  │ true (pause) /      │  │
│  │ PLAYING/STOPPED│   │  │ false (resume)      │  │
│  │ / PAUSED       │   │  └────────────────────┘  │
│  └────────────────┘   │  ReverseDecodeDispatcher  │
│                       │  ┌─ interrupt ─────────┐  │
│                       │  │ true / false        │  │
│                       │  └────────────────────┘  │
└──────────────────────┴───────────────────────────┘
```

## 2. HurricaneState — QML 前端播放器状态机

**文件:** [src/player/hurricane.hpp](..\src\player\hurricane.hpp)

这是 PonyPlayer 最核心的、面向 QML 前端的播放器状态机。它定义了播放器对用户可见的全部宏观状态。

### 2.1 状态枚举

```cpp
enum HurricaneState {
    CLOSING,       // = 0  正在关闭当前文件（瞬时状态）
    LOADING,       // = 1  正在加载文件（瞬时状态）
    INVALID,       // = 2  无有效文件打开（稳定状态）
    PRE_PLAY,      // = 3  准备播放（瞬时状态）
    PLAYING,       // = 4  正在播放（稳定状态）
    PRE_PAUSE,     // = 5  请求暂停（瞬时状态）
    PAUSED         // = 6  已暂停（稳定状态）
};
```

**设计理念：**
- **瞬时状态**（CLOSING, LOADING, PRE_PLAY, PRE_PAUSE）表示前端发起了操作但后端尚未同步完成。瞬时状态随时可能被新操作打断而跳过其目标稳定状态。
- **稳定状态**（INVALID, PLAYING, PAUSED）对应后端实际的工作状态，由后端信号驱动进入。
- **关键规则：不应检测瞬时状态来决定下一步动作**。例如 PRE_PAUSE 可能被 close() 打断，直接转移到 INVALID 而永远不会到达 PAUSED。

### 2.2 状态转移图

```
                         ┌─────────┐
                         │ INVALID │ (初始状态)
                         └────┬────┘
                              │ openFile()
                              ▼
                         ┌─────────┐
                    ┌───►│ LOADING │ (瞬时)
                    │    └────┬────┘
                    │         │
                    │    ┌────┴────────────┐
                    │    │ 文件打开结果?    │
                    │    └────┬────────────┘
                    │    失败 │      │ 成功
                    │         │      ▼
                    │    ┌────┴────────────┐
                    │    │ slotOpenFile-   │
                    │    │ Result(FAILED)  │
                    │    │ state = INVALID │
                    │    └────────────────┘
                    │
                    │         ┌──────────┐
                    │         │  PAUSED  │ (稳定)
                    │         └────┬─────┘
                    │              │ start()
                    │              ▼
                    │         ┌──────────┐
                    │         │ PRE_PLAY │ (瞬时)
                    │         └────┬─────┘
                    │              │ 后端 onWork() 启动
                    │              ▼
                    │         ┌──────────┐
                    │         │ PLAYING  │ (稳定)
                    │         └────┬─────┘
                    │              │ pause()
                    │              ▼
                    │         ┌───────────┐
                    │         │ PRE_PAUSE │ (瞬时)
                    │         └────┬──────┘
                    │              │ 后端 onWork() 停止
                    │              ▼
                    │         ┌──────────┐
                    │         │  PAUSED  │ (稳定)
                    │         └────┬─────┘
                    │              │ close()
                    │              ▼
                    │         ┌──────────┐
                    │         │ CLOSING  │ (瞬时)
                    │         └────┬─────┘
                    │              │ 后端 close() 完成
                    └──────────────┘
```

### 2.3 完整状态转移表

| 当前状态 | 操作 | 新状态 | 类型 | 备注 |
|---------|------|--------|------|------|
| INVALID / CLOSING | `openFile()` | LOADING | 前端触发 | 如果当前是 CLOSING 则先等待完成 |
| LOADING | 打开成功 (信号) | PAUSED | 后端驱动 | slotOpenFileResult |
| LOADING | 打开失败 (信号) | INVALID | 后端驱动 | slotOpenFileResult |
| PAUSED / PRE_PAUSE | `start()` | PRE_PLAY | 前端触发 | 发送 signalStart |
| PRE_PLAY | 后端启动完成 | PLAYING | 后端驱动 | slotPlaybackStateChanged(true) |
| PLAYING / PRE_PLAY | `pause()` | PRE_PAUSE | 前端触发 | 发送 signalPause |
| PRE_PAUSE | 后端暂停完成 | PAUSED | 后端驱动 | slotPlaybackStateChanged(false) |
| PAUSED / PRE_PAUSE | `close()` | CLOSING | 前端触发 | 清空视频帧 |
| PLAYING / PRE_PLAY / PAUSED / PRE_PAUSE | `seek()` | PRE_PAUSE | 前端触发 | 如果原是播放态，seek 后自动 start |
| PLAYING | 资源播放完毕 (信号) | PAUSED | 后端驱动 | resourcesEnd → 直接 PAUSED（跳过 PRE_PAUSE） |

### 2.4 QML 侧状态同步

QML 侧通过 `solveStateChanged()` ([interfacefunctions.js:377](..\src\view\interfacefunctions.js#L377)) 处理状态变化：

| HurricaneState 值 | QML 行为 |
|-------------------|----------|
| LOADING (1) | `toVideoBegining()` — 重置进度到开头 |
| INVALID (2) | `endTime = 0` + `toVideoBegining()` |
| PLAYING (4) | `isPlay = true` |
| PAUSED (6) | `isPlay = false` |

## 3. Playback 内部状态 — 音视频输出状态

**文件:** [src/player/playback.hpp](..\src\player\playback.hpp)

Playback 类负责将解码后的帧输出到音频设备和视频渲染器。其内部使用两个原子布尔变量管理运行状态。

### 3.1 状态变量

| 变量 | 类型 | 含义 |
|------|------|------|
| `m_isPlaying` | `std::atomic<bool>` | 是否正在输出音视频 |
| `m_isInterrupt` | `std::atomic<bool>` | 是否收到中断/停止请求 |

### 3.2 状态转移

```
m_isInterrupt = false ──────────────────────────────────────────
    │                                                            │
    │ start() / setStartPoint()                                  │ pause() / stop()
    ▼                                                            ▼
┌─────────┐   onWork() 获取到帧    ┌──────────┐   资源耗尽    ┌──────────┐
│  空闲   │ ───────────────────►  │  工作中   │ ───────────► │  空闲     │
│ (!work) │                       │ (working) │              │ (!work)   │
└─────────┘                       └──────────┘              └──────────┘
                                       │                         ▲
                                       │ changeState(true)       │ changeState(false)
                                       ▼                         │
                                  emit stateChanged(true)   emit stateChanged(false)
```

### 3.3 关键操作

| 方法 | 行为 | m_isInterrupt | 阻塞 |
|------|------|:---:|:---:|
| `start()` | 发送 startWork 信号，onWork() 开始运行 | false | 否 |
| `pause()` | 设置中断标志 + 唤醒 cond_var + 获取 workMutex | true | **是**（等当前帧处理完） |
| `stop()` | pause() + 发送 stopWork/clear 信号 | true | **是** |
| `setStartPoint()` | 重置中断标志 + 设置音频起始点 | false | 否 |

### 3.4 onWork() 主循环

```
onWork() 获取 workMutex
  ├── changeState(true)  → emit stateChanged(true)
  ├── writeAudio(5)
  ├── m_audioSink->start()
  └── while (!m_isInterrupt):
       ├── getVideoFrame() → 无效则 resourcesEnd(), break
       ├── emit setPicture(frame)
       ├── writeAudio(batch)
       ├── syncTo(frame.pts)  ← 音频时钟同步
       └── processEvents()
  └── m_audioSink->pause()
  └── changeState(false) → emit stateChanged(false)
```

## 4. PlaybackState — 音频设备状态机 (PonyAudioSink)

**文件:** [src/audiosink/audiosink.hpp](..\src\audiosink\audiosink.hpp)

PonyAudioSink 封装了 PortAudio 音频后端，管理音频设备的播放状态。

### 4.1 状态枚举

```cpp
enum class PlaybackState {
    PLAYING,   // PortAudio stream 正在运行
    STOPPED,   // stream 已中止（Abort），缓冲区被清空
    PAUSED,    // stream 已停止（Stop），缓冲区数据保留
};
```

### 4.2 状态转移图

```
                    ┌──────────┐
           ┌──────►│  STOPPED │◄─────────┐
           │       └────┬─────┘          │
           │ start()    │                │ stop() (AbortStream)
           │            │                │
           │            ▼                │
           │       ┌──────────┐          │
           │       │ PLAYING  │──────────┤
           │       └────┬─────┘          │
           │            │ pause()        │
           │            │ (StopStream)   │
           │            ▼                │
           │       ┌──────────┐          │
           └───────│  PAUSED  │──────────┘
           start() └──────────┘  stop()
```

### 4.3 关键区别: PAUSED vs STOPPED

| 特性 | PAUSED (StopStream) | STOPPED (AbortStream) |
|------|--------------------|------------------------|
| 音频缓冲区 | 保留 | 清空 |
| start() 后 | 从暂停点继续 | 从头开始 |
| setStartPoint() | 无效（仅在 STOPPED 时有效） | 有效 |
| 典型场景 | 用户暂停 | 关闭文件/seek |

### 4.4 阻塞状态 (m_blockingState)

当播放速度超过 `MAX_SPEED_FACTOR` (4x) 时，PonyAudioSink 进入阻塞模式：

- `isBlock() = true`：回调中输出静音（memset 0），不消耗缓冲区数据
- `isBlock() = false`：正常从 ring buffer 读取数据输出

## 5. DecodeDispatcher 中断状态 — 解码管线运行/暂停

**文件:** [src/decoder/private/dispatcher.hpp](..\src\decoder\private\dispatcher.hpp)

### 5.1 正向解码 (DecodeDispatcher)

```cpp
std::atomic<bool> interrupt = true;  // 初始为暂停状态
```

| 方法 | 行为 | interrupt |
|------|------|:---:|
| `statePause()` | 设置 interrupt=true + 关闭队列 | true |
| `stateResume()` | 设置 interrupt=false + 打开队列 + 发信号启动 | false |
| `seek()` | 设置 interrupt=true + av_seek_frame + flush 解码器 | true |
| `onWork()` | while(!interrupt) 循环读取/解码帧 | — |

### 5.2 反向解码 (ReverseDecodeDispatcher)

与正向相同的中断机制，额外逻辑：

- 反向解码按 5 秒为一个 segment 分段读取
- 遇到 EOF 时自动 seek 到前一个 segment
- `nextSegment()` 返回 0 表示到达文件起点

### 5.3 状态转移

```
    ┌──────────┐
    │  暂停    │ (interrupt = true, queue closed)
    └────┬─────┘
         │ stateResume()
         ▼
    ┌──────────┐
    │  运行    │ (interrupt = false)
    │ onWork() │ ──── av_read_frame + decoder.accept() 循环
    └────┬─────┘
         │ statePause() / seek() / EOF
         ▼
    ┌──────────┐
    │  暂停    │
    └──────────┘
```

## 6. Demuxer 方向状态 — 正放/倒放/关闭

**文件:** [src/decoder/demuxer.hpp](..\src\decoder\demuxer.hpp)

Demuxer 通过 `m_worker` 指针在正向和反向解码器之间切换。

### 6.1 状态

| m_worker 值 | 含义 |
|:-----------:|------|
| `nullptr` | 无文件打开 |
| `m_forward` (DecodeDispatcher*) | 正向播放 |
| `m_backward` (ReverseDecodeDispatcher*) | 倒放 |

### 6.2 状态转移

```
                  openFile() 成功
    ┌────────┐ ─────────────────► ┌──────────┐
    │ nullptr│                    │ m_forward│ (默认正放)
    └────────┘ ◄───────────────── └────┬─────┘
                  close()              │
                                       │ backward()
                                       ▼
                                  ┌──────────┐
                                  │m_backward│ (倒放)
                                  └────┬─────┘
                                       │ forward()
                                       │
                                       ▼
                                  ┌──────────┐
                                  │ m_forward│ (恢复正放)
                                  └──────────┘
```

### 6.3 判断当前方向

```cpp
bool isBackward() {
    return dynamic_cast<ReverseDecodeDispatcher *>(m_worker);
}
// 返回 true 时为倒放
```

## 7. OpenFileResultType — 文件打开结果枚举

**文件:** [src/decoder/private/dispatcher.hpp](..\src\decoder\private\dispatcher.hpp)

```cpp
namespace PonyPlayer {
    enum OpenFileResultType {
        FAILED,   // 打开失败（文件损坏、格式不支持、无音频流）
        VIDEO,    // 视频文件（含音频流+视频流）
        AUDIO     // 纯音频文件（仅音频流）
    };
}
```

### 7.1 判断逻辑 (DecodeDispatcher 构造函数)

```
打开文件 → 检测流类型
  ├── 无音频流 → FAILED
  ├── 后缀为 .mp3/.wav → AUDIO（isAudio = true）
  └── 其他 → VIDEO
```

- AUDIO 模式：创建 VirtualVideoDecoder 代替真实视频解码器
- VIDEO 模式：创建 DecoderImpl\<Video\> 解码视频流

## 8. TwinsBlockQueue 启用状态 — 队列开关

**文件:** [src/utils/include/twins_queue.hpp](..\src\utils\include\twins_queue.hpp)

TwinsBlockQueue 是一个双胞胎阻塞队列，视频队列和音频队列共享同步机制。

### 8.1 状态

```cpp
// 队列启用状态
void setEnable(bool b);     // true = 启用，false = 禁用
bool isEnable();            // 查询当前状态
void open();                // 打开队列（允许 push/remove 操作）
void close();               // 关闭队列（唤醒所有等待的消费者）
```

### 8.2 典型使用场景

- **音频禁用:** 高速播放时 `audioQueue->setEnable(false)`，避免音频缓冲区溢出
- **队列关闭:** `statePause()` 时 `videoQueue->close()` 唤醒阻塞在 `remove()` 上的消费者线程

## 10. 状态机间的层级关系

### 10.1 一次典型播放操作的完整状态流转

```
用户点击播放按钮
  │
  ▼
[QML] isPlay = true, emit start() signal
  │
  ▼
[Hurricane] PAUSED → PRE_PLAY, emit signalStart()
  │
  ▼
[FrameController] start() → m_demuxer->start() + m_playback->start()
  │
  ├──► [Demuxer/DecodeDispatcher] stateResume(): interrupt=false
  │       └── onWork() 开始循环解码
  │
  └──► [Playback] emit startWork()
          └── onWork():
                ├── changeState(true) → Hurricane: PLAYING → QML: isPlay=true
                ├── [PonyAudioSink] start(): STOPPED → PLAYING
                ├── while(!interrupt): getVideoFrame + writeAudio + syncTo()
                └── 结束 → changeState(false) → Hurricane: PAUSED
```

### 10.2 一次 seek 操作的完整状态流转

```
用户拖动进度条
  │
  ▼
[Hurricane] state → PRE_PAUSE, emit signalSeek(pos)
  │
  ▼
[FrameController] seek():
  ├── m_playback->stop()     → PonyAudioSink: PLAYING/PAUSED → STOPPED
  ├── m_demuxer->pause()     → DecodeDispatcher: interrupt=true
  ├── m_demuxer->seek(pos)   → av_seek_frame (阻塞)
  ├── m_demuxer->flush()     → 清空队列中的旧帧
  ├── m_demuxer->start()     → DecodeDispatcher: interrupt=false
  ├── skipPicture/skipSample → 跳过 seek 点之前的帧
  ├── m_playback->setStartPoint()
  └── m_playback->showFrame()
```

### 10.3 状态机层级关系表

| 层级 | 状态机 | 所在线程 | 同步机制 |
|------|--------|---------|----------|
| QML UI | `isPlay`, `isInverted`, `playState`, UI visibility | MAIN | Qt signals/slots |
| C++ 桥接 | `HurricaneState` | MAIN | `Q_ENUM` + signals |
| 帧调度 | `FrameController` | FRAME | Qt signals (QueuedConnection) |
| 音视频输出 | Playback `m_isPlaying` / `m_isInterrupt` | PLAYBACK | `std::atomic` + mutex |
| 音频设备 | `PonyAudioSink::PlaybackState` | PLAYBACK | mutex (`paStreamLock`) |
| 解码管线 | `DecodeDispatcher::interrupt` | DECODER | `std::atomic<bool>` |
| 播放方向 | `Demuxer::m_worker` | DECODER | mutex (`m_workerLock`) |
| 队列状态 | `TwinsBlockQueue::isEnable` | DECODER/FRAME | 内置互斥锁 |
