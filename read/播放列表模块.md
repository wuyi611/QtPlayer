# PonyPlayer 播放列表模块（playlist/）依赖与调用关系

> 本文档梳理 `src/playlist/` 目录下各文件的职责、静态依赖（include）关系与运行时调用链。
> 生成于 2026-08-16。

---

## 一、模块定位与目录结构

播放列表模块（又称**媒体库层**）是 PonyPlayer 的**数据层**：向上以 QML 组件 `Controller` 暴露给界面层（view/），向下用 `PlayList` 在独立线程中操作 SQLite 数据库（媒体库），并用 `infoAccessor` 基于 FFmpeg 提取媒体文件的元信息与预览图。整体是"QML 界面（GUI）→ Controller（GUI 线程桥接）→ PlayList（工作线程）→ KV Engine（SQLite）+ InfoAccessor（FFmpeg）"的分层结构。

```
src/playlist/
├── CMakeLists.txt            构建配置（静态库 playlist，链接 Qt Core/Gui/Quick/Sql + utils）
├── include/
│   ├── controller.h          Controller 声明（QML 前端桥接 / 门面）
│   ├── playlist.h            PlayList / PlayListItem / simpleListItem 声明
│   ├── kv_engine.h           PonyKVConnect / PonyKVList<T> / ListItem 声明
│   └── info_accessor.h       infoAccessor 声明（FFmpeg 元信息提取）
├── controller.cpp            Controller 实现
├── playlist.cpp              PlayList / PlayListItem 实现
├── kv_engine.cpp             PonyKVConnect / PonyKVList<T> 实现
└── info_accessor.cpp         infoAccessor 实现（FFmpeg 解析 + 首帧预览）
```

依赖关系（构建层面）：`playlist` 链接 `utils`（PonyPlayer::getHome / PONYPATH / INCLUDE_FFMPEG 宏）以及 Qt Core/Gui/Quick/Sql。

## 二、各文件职责

| 文件 | 作用 |
|---|---|
| `controller.h/cpp` | **模块入口 / QML 门面**。注册为 QML 类型 `Controller`（由 `src/main.cpp` 的 `qmlRegisterType<Controller>("Controller",1,0,"Controller")` 调用）。持有 `QThread listOPThread` 并把 `PlayList` `moveToThread` 到该线程。对外暴露 `Q_INVOKABLE`：`getSimpleListItemList` / `getRecentFiles` / `updateRecentFile` / `getListItemInfo`，以及 `recentFiles` 只读属性（`NOTIFY recentFilesChanged`）。负责把前端请求转发到 PlayList 的槽，并接收 PlayList 的完成信号缓存结果、转发回 QML。 |
| `playlist.h/cpp` | **后端数据操作层**。`PlayList` 是数据库操作者，运行在 `listOPThread`；提供 `insert/remove/search/extractAndProcess/getInfo` 槽，并通过 `insertDone/removeDone/searchDone/extractDone/getInfoDone` 信号回传。`PlayListItem`（继承 `ListItem`）是完整媒体条目模型（含视频/音频编码参数）；`simpleListItem` 是播放列表左侧列表项用的简化模型（文件名/路径/预览图）。 |
| `kv_engine.h/cpp` | **KV 存取引擎**。`PonyKVConnect` 基于 SQLite + Qt 反射（`metaObject` 属性）动态建表、插入/删除/查询对象；`PonyKVList<T>` 是面向某类型表/某类的类型化 CRUD 封装；`ListItem` 是所有条目对象的基类（含 `_uuid_` 主键）。 |
| `info_accessor.h/cpp` | **媒体信息提取器**。基于 FFmpeg（`avformat` / `avcodec` / `swscale`）解析一个媒体文件的帧率、码率、时长、封装格式、视频/音频流参数等，写入 `PlayListItem`，并提取视频首帧生成 PNG 预览图返回其 URL。 |

### 关键事实

- `kv_engine.h` 是最底层，被 `playlist.h` 依赖；`playlist.h` 又被 `controller.h` 与 `info_accessor.h` 依赖，是全模块的**汇聚点**。
- `kv_engine.cpp` 与 `info_accessor.h` 都依赖 `ponyplayer.h`（utils 模块）：前者用 `PonyPlayer::getHome()`，后者用 `INCLUDE_FFMPEG_BEGIN/END` 宏与 `PONYPATH` 环境变量。
- `info_accessor.h` 直接 include FFmpeg 头文件（经 `INCLUDE_FFMPEG_*` 包裹），是模块内唯一的 FFmpeg 耦合点；`playlist` 通过 CMake 链接 `utils` 才能解析 `ponyplayer.h`。
- `Controller` 与 `PlayList` 之间通过**信号-槽 + 跨线程队列连接**通信，二者不在同一线程。

## 四、类继承关系

```
QObject
 ├─ ListItem                      条目基类（Q_PROPERTY _uuid_ 主键）
 │   └─ PlayListItem              完整媒体条目（继承 ListItem，含全部音视频元信息属性）
 ├─ PlayList                      播放列表后端数据操作者（持有 PonyKVList<PlayListItem>）
 ├─ Controller                    QML 前端控制器（持有 QThread listOPThread）
 └─ simpleListItem                列表项简化模型（文件名/路径/预览图）

非 QObject 类：
 PonyKVConnect                    SQLite 存取引擎（反射式 CRUD）
 PonyKVList<T>                    类型化 CRUD 封装（持有 PonyKVConnect）
 infoAccessor                     媒体元信息提取（静态方法 getInfo）
```

- `PlayListItem` / `simpleListItem` / `PlayListItem*` 均已声明 `Q_DECLARE_METATYPE`（`PlayListItem*` 在 `main.cpp` 另用 `qRegisterMetaType` 注册），以便在队列连接的信号中传递。
- `PonyKVList<PlayListItem>` 在 `kv_engine.cpp` 末尾显式实例化（`template class PonyKVList<PlayListItem>;`），保证链接期生成模板实现。

## 五、运行时调用链

### 5.1 构造阶段（main → QML 注册 → Controller 构造 → 线程启动）

```
main.cpp: qmlRegisterType<Controller>("Controller",1,0,"Controller")
         qmlRegisterType<PlayList>("PlayList",1,0,"PlayList")
         qmlRegisterType<simpleListItem>("SimpleListItem",1,0,"SimpleListItem")
         qRegisterMetaType<PlayListItem*>("PlayListItem")

QML 创建 Controller（GUI 线程）
 └─ Controller::Controller（构造器）
     ├─ new PlayList("MediaLib","MediaInfo","PlayListItem")   ← 后端数据库操作对象
     ├─ listOPer->moveToThread(&listOPThread)                 ← 移入工作线程
     ├─ 请求连接：insertItem→insert / searchItem→search / extractRequirement→extractAndProcess
     │            removeRequirement→remove / getInfoRequirement→getInfo
     ├─ 结果连接：insertDone→getInsertRst / removeDone→getRemoveRst / searchDone→getSearchRst
     │            extractDone→getExtractRst / getInfoDone→getInfoRst
     ├─ connect(&listOPThread, &QThread::finished, listOPer, &QObject::deleteLater)
     └─ listOPThread.start()
```

### 5.2 播放列表加载（QML 启动 → 提取全部条目）

```
QML Component.onCompleted → mediaLibController.sendExtractRequirement()
 └─ emit extractRequirement ──(队列)──► PlayList::extractAndProcess（listOPThread）
     ├─ pkvList.extract() 取出全部 PlayListItem
     ├─ 逐个转换为 simpleListItem(fileName,path,iconPath)
     └─ emit extractDone(res) ──(队列)──► Controller::getExtractRst
         └─ 缓存 result + emit finishExtractItems
             └─ QML onFinishExtractItems → getSimpleListItemList() → 填充 listModel（左侧列表）
```

### 5.3 添加文件（打开文件后入库）

```
videoListOperatorOnAccepted(path)
 ├─ mediaLibController.updateRecentFile(acceptedFileName)   ← 写最近播放记录
 ├─ mediaLibController.getFile(fileName, path)              ← Controller::getFile
 │    ├─ new PlayListItem → infoAccessor::getInfo(path, *info)  ← FFmpeg 解析 + 首帧预览图
 │    ├─ 打印各参数调试日志
 │    └─ emit insertItem(info) ──(队列)──► PlayList::insert
 │        └─ pkvList.insert(item) → PonyKVConnect::insert（写 SQLite）
 └─ listModel.append(...)  ← QML 本地同步追加（前端已可见）
```

### 5.4 查看媒体信息（双击列表项）

```
onDoubleClicked → mediaLibController.sendGetInfoRequirement(filePath)
 └─ emit getInfoRequirement ──(队列)──► PlayList::getInfo
     ├─ pkvList.extractInfo("path", path) → PonyKVConnect::search
     └─ emit getInfoDone(item) ──(队列)──► Controller::getInfoRst
         └─ 缓存 playListItemResult + emit finishGetInfo
             └─ QML onFinishGetInfo → getListItemInfo() → 填充 mediainfowindow.infomodel
```

### 5.5 删除条目（列表项删除按钮）

```
onClicked → mediaLibController.sendRemoveRequirement(filePath, iconPath)
 └─ emit removeRequirement ──(队列)──► PlayList::remove
     ├─ pkvList.remove("path", filePath) → PonyKVConnect::removeByKV
     │    ├─ search 出该条目 → 删除其预览图文件（若存在）
     │    └─ DELETE FROM 表 WHERE path=:value
     └─ emit removeDone ──(队列)──► Controller::getRemoveRst（打印日志）
```

### 5.6 最近打开文件（属性读取 + 更新）

```
读取：QML `model: mediaLibController.recentFiles`（Q_PROPERTY）
      → Controller::getRecentFiles() 读 PONYPATH/recentOpenFiles.txt，逐行按 "," 拆成 [文件名,路径]

更新：updateRecentFile(filePath)
      → 读旧记录，去重并把最新一条放到最前，最多保留 10 条
      → 以截断模式重写文件 → emit recentFilesChanged（触发 QML 刷新）
```

## 六、跨文件数据流

```
[QML main.qml / interfacefunctions.js]
   │  sendExtractRequirement / sendRemoveRequirement / sendGetInfoRequirement / getFile / updateRecentFile
   ▼
[Controller]（GUI 线程）
   │  emit extractRequirement / removeRequirement / getInfoRequirement / insertItem
   ▼（跨线程队列连接）
[PlayList]（listOPThread 工作线程）
   │  insert / remove / search / extractAndProcess / getInfo
   ▼
[PonyKVList<PlayListItem>] ──► [PonyKVConnect]（SQLite：MediaLib.db）
   │                                        ▲
   │   extractInfo / extract                 │ insert / remove / search / retrieveData
   ▼                                        │
[infoAccessor::getInfo]（FFmpeg）            │
   │  解析元信息 + 生成预览图 ────────────────┘（写入 PlayListItem）
   ▼
[QML 左侧列表 / 媒体信息面板] ◄── extractDone / getInfoDone / recentFilesChanged（队列连接回 GUI）
```

## 七、线程模型

```
MAIN/GUI 线程    ← Controller、QML（main.qml / interfacefunctions.js）
listOPThread     ← PlayList（moveToThread 移入，全部数据库操作在此执行）
```

- `PlayList` 通过 `moveToThread(&listOPThread)` 移至后台线程，所有数据库操作（建表/增删查）不阻塞 UI。
- 线程结束连接：`connect(&listOPThread, &QThread::finished, listOPer, &QObject::deleteLater)`，避免内存泄漏。
- 跨线程通信原则：**控制请求走 Qt 队列连接**（Controller 信号 → PlayList 槽，自动按线程归属排队）；**结果回传同样是队列连接**（PlayList 信号 → Controller 槽），落在 GUI 线程执行。
- 数据目录：`PonyKVConnect` 构造函数里通过 `PonyPlayer::getHome()` 取得用户目录并设置 `PONYPATH` 环境变量，`data/`（SQLite）与 `preview/`（预览图）均建于其下。

## 八、注意点与隐患

1. **`PlayList::search` 为占位实现**：恒 `return NULL`，对应 `searchItem→search` 与 `searchDone→getSearchRst` 连接形同虚设，按主键搜索功能实际未实现。
2. **`createTableFrom` 主键判定疑似失效**：用 `!strcmp(metaObj->property(i).name(), "__uuid__")` 判断主键，但属性名实际为 `_uuid_`，比较恒不等，导致建表时 `PRIMARY KEY` 从不被追加，`_uuid_` 列没有主键约束。
3. **`removeByKV` 空指针风险**：先 `search<PlayListItem>` 再解引用 `pli->getIconPath()`；若条目不存在，`search` 内部 `while(query.next())` 未命中时仍 `newInstance()` 返回一个默认对象（非 nullptr），因此不会崩溃但会得到一个空属性对象；`search` 无法区分"未找到"与"找到默认实例"。
4. **对象生命周期管理缺失**：`Controller::getFile` 中 `new PlayListItem` 后经 `emit insertItem(info)` 跨线程交给 `PlayList::insert`，该指针只被 `PonyKVList::insert` 存入缓存并写库，此后无 `deleteLater`/所有权转移，存在泄漏风险。
5. **SQL 字符串拼接注入风险**：`insert` 对值用 `std::quoted` 转义，但 `remove`/`removeByKV`/`createTableFrom` 把表名、列名、键值（`key`）直接拼进 SQL，未参数化，存在注入风险（`removeByKV` 的删除部分用了参数化，但 `search` 部分未参数化）。
6. **`qTypeToDDL` 类型覆盖不全**：查找表只映射 `QString/QDir/float/int`；若类属性出现其他类型，`lookUpTable[qType]` 会插入默认构造的空字符串，生成的 DDL 非法。
7. **`PonyKVConnect` 数据库连接名未指定**：`QSqlDatabase::addDatabase("QSQLITE")` 未传连接名，多次构造会复用/覆盖默认连接；若模块内创建多个 `PonyKVConnect` 实例可能互相冲突。
8. **跨线程信号参数类型注册**：`extractDone(QList<simpleListItem*>)` 走队列连接时要求 `QList<simpleListItem*>` 已 `qRegisterMetaType`；当前只在 `playlist.h` 声明了 `Q_DECLARE_METATYPE(simpleListItem)`，未对 `QList<simpleListItem*>` 注册，队列连接下可能告警/失败。
9. **`Controller::getRecentFiles`/`updateRecentFile` 依赖 `PONYPATH`**：若 `PONYPATH` 未设置（未经 `PonyKVConnect` 构造初始化），`home` 为空字符串，读写 `recentOpenFiles.txt` 会失败（仅 `qDebug` 提示，不中止）。
10. **`getFile` 中的 `infoAccessor::getInfo` 失败路径**：文件打不开或读流失败时直接 `return ""`，此时 `PlayListItem` 已 `new` 出来但元信息为空，仍会 `emit insertItem` 插入一条空记录（无预览图，`iconPath` 为空串）。
